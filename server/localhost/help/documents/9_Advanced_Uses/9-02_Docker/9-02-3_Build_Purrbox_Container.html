Build Purrbox Container

The following will build a generic container that can be used to run Purrbox in either Node.js modes (CommonJS or ECMAScript), allow container deployment with bind mounts or use environment variables to manage server and logging settings. It can also be enabled for Management UI, disabled to only host one website or multiple websites via many domain name mappings.


Buildx Script

Start by logging into the server as the 'purrbox' user account and make sure you are in the purrbox home drive. Create a buildx script as shown below. 

$ cd ~

$ pwd
/home/purrbox

$ mkdir purrbox

$ nano ~/purrbox/buildx-script

Note that there is some commented out lines that can be used to use a different development branch. 

   
   FROM node:22.14.0-alpine3.21

   # Update server
   RUN apk update
   RUN apk upgrade
   RUN apk add git

   # Clone software
   RUN mkdir /www
   WORKDIR /www
   RUN git clone https://github.com/spectrumitec/purrbox.git /www

   # Use to switch github branch
   #RUN git switch "alternate-branch"
   #RUN git pull

   # Make other directories
   RUN mkdir /www/logs /www/web_source /www/web_templates

   # Configure Node modules and prep directory
   RUN npm install ip bcrypt crypto jsonwebtoken syslog-client
   RUN rm -fr .github .gitignore vhost_server.service README.md

   # Clean up git
   RUN apk del git

Save the file and run the buildx docker command to build the base container. 

$ cd ~/purrbox

$ docker buildx build --no-cache -f ~/purrbox/buildx-script -t purrbox:latest .

Verify the container image exists after build. 

$ docker images
REPOSITORY   TAG       IMAGE ID       CREATED         SIZE
purrbox      latest    5879a9c2f407   5 seconds ago   200MB

Test the purrbox container starts up and runs. The following is a basic start up of the container with exposed ports 80 and 443. Note that you will need to set the hostname, FQDN, and/or IP address to access the Management UI from the test. Make sure to use the IP address of your server as '192.168.50.198' is an example. 

$ docker run --rm -it --entrypoint sh \
-e PURRBOX_MGMT_UI="192.168.50.198" \
-p 80:80 \
-p 443:443 \
purrbox:latest

The container should start and run. Since this is a new temporary container, purrbox will generate new config files like the 'server_conf.json' inside the container in '/www/conf/' folder. Once you are at the command line of the container, run the 'node start_server.js' to run the CommonJS mode. To run the ECMAScript mode you would instead run 'node start_server.mjs'.

The environment variable defined will override the default server config and append the IP address you set above. You will notice the 'Management UI Hostnames' has things like localhost, 127.0.0.1, the docker container IP, docker container hostname which are detected on start up. Typically, those enteries are not resolvable from outside the container so you would not be able to access the 'Management UI' from those names. 

/www # node start_server.js

Since the temporary run exposes port 80 and 443, and you defined your IP address as an environment variable, the web server should be accessible via the server IP and the port specified. At this point you should be able to open a browser and connect to the server IP to access the page. Since it will be a default self-signed SSL certificate, you will get an error message that the site is not safe and will have to accept to continue.



At this point if you can login to the web page with default credentials, you will know your container is correctly built. Now you can 'CTRL+C' to stop the web server from your container and exit the contaienr command line which will then clean up the running container. You can now start thinking about what server modes and configuration settings you would like to have and continue to creating a compose YAML for standing up one or more Purrbox containers.
